Section 3

Discovering assets and baselining the current state

Organizations already run an average of 12 agents, and half of them operate in silos rather than as part of a coordinated system.2 Because nothing can be governed until it is visible, Phase 1 of the handbook’s phased plan starts with an inventory: register every agent, API and MCP server, then route model and tool traffic through one gateway. Discovery applies the same idea to one use case: find every asset it touches, who owns it and how it is controlled today, and measure how the process performs before anything changes.

How to run discovery

  1. Send the data request first. Ask for the documents and data below a week before the first workshop, so the workshops can confirm what the client has already sent.
  2. Walk the process with the people who do it. Use real, recent examples. Note every hand-off, re-keying step and wait.
  3. Inventory the AI estate. List agents in production, pilot and planning on every platform, with owners and autonomy. Add the models, providers, contracts and data-retention terms, and the APIs, events and MCP servers. Where the client allows, run Agent Scanners to discover agents and MCP servers across ecosystems.21 Record each agent’s sponsor, and which native control plane, such as Agent 365, Amazon Bedrock AgentCore, Gemini Enterprise Agent Platform or Agentforce, already governs it.
  4. Trace the data. For each agent, find the master data it depends on, its golden record (if any), quality issues, sensitivity and lineage.
  5. Find the policies. Record the approvals, limits, data rules and regulations that apply, where each is enforced today and where it is only written down.
  6. Validate with the owners. Every row in the inventory has an owner who has confirmed it. Unknowns become open questions in T12.

Finding shadow agents

Shadow agents are common: in a survey Microsoft commissioned, 29% of employees had turned to unsanctioned AI agents for work tasks.9 Personal and team-built agents often run outside any inventory, on laptops or in SaaS tools, with access to email, files and credentials. Ask about them directly, check endpoint and identity logs where the client permits, and make the governed path the easy path: a registry, a gateway and sanctioned capabilities that agents can use safely. Decoy credentials and decoy MCP tools that no sanctioned agent should touch can reveal agents working outside the governed path. A custom gateway policy family can plant and watch such decoys (handbook Section 7).

Every agent has a lifecycle

Agents need the same lifecycle discipline as the people and systems they work alongside. Deloitte recommends managing agents much like a workforce, from onboarding and digital identities to human supervisors at key decision points and, eventually, retirement planning.13 Microsoft’s Cloud Adoption Framework calls for one governance layer that enforces identity, ownership, access control and monitoring for every agent.14 Record where each agent stands:

In T3d, give every agent a sponsor, its lifecycle stage, its next recertification date and its retirement criteria. Agents without an owner are the ones that linger: assign a sponsor at registration and move sponsorship when people change roles, as Microsoft Entra Agent ID does automatically to prevent orphaned agents.12

Baselining the KPIs

Measure the process before it changes, in the scope the first phase will cover. Use system timestamps where they exist (for example, from the event that starts the process to the one that ends it), a short time study for manual effort, and finance data for cost and revenue effects. Agree the method and the numbers with the business owner and the finance partner (template T6).

A baseline of “not measured” is a finding in its own right. For most clients, governed AI traffic, AI cost per outcome and agent evaluation pass rates are not measured at all today. The first phase makes them visible. Cost visibility is a common gap: in KPMG’s second-quarter 2026 pulse, only 26% of organizations had full, real-time visibility into what their AI systems cost to operate.8

The data request

  • Process documentation, volumes and service levels for the use case. Recent examples of cases that went well and badly.
  • Application portfolio or CMDB extract for the systems involved, with owners and hosting.
  • API catalog (for example, MuleSoft Exchange), integration inventory and any MCP servers in use.
  • List of AI agents and copilots in production and pilot, with platform, owner, sponsor and purpose, and any agent control planes already in use (such as Agent 365, Amazon Bedrock AgentCore or Agentforce).
  • Model provider contracts or terms (data retention, regions), and AI spend for the last quarter by owner and use case if available, ideally as billing data in the FinOps Foundation’s FOCUS format.23
  • Data catalog or MDM documentation for the domains involved, with known quality issues.
  • Security policies for identity, access, data classification and approvals. Applicable regulations and audit findings.
  • Baseline data for the candidate KPIs: cycle times, effort, error or exception rates, cost and revenue effects.
