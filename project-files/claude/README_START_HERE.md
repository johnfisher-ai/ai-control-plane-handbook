## Conventions

- **Naming rule (applies everywhere):** the word "[banned word]" must not appear in any document, slide, speaker note, figure, caption, file property, endnote commentary or discussion. Refer to integration capabilities as MuleSoft (for example MuleSoft connectors, System and Process APIs, MCP Bridge) and to the control plane as MuleSoft Agent Fabric. CloudHub is allowed: it is the runtime for Agent Fabric. Runtime Fabric is also allowed.
- **Replacement wording in use:** "MuleSoft" as the integration label (for example "Capabilities and data (MuleSoft)"), "MuleSoft APIs", "MuleSoft connectors", "MuleSoft Exchange", "its API-led connectivity" where a sentence needs an actor, and "MuleSoft: unlocking enterprise applications" as the Section 3 subsection and slide 8 title.
- Audience is CTO/CIO; plain, direct English; no marketing superlatives without evidence.
- Naming sources (John, September 30, 2026): analyst, publisher and magazine names (for example Deloitte, Gartner, Forbes, HCLTech, the Forrester Wave and CDO Magazine) may appear in the text as long as the sentence carries its endnote. Company names (for example Google) and product names (for example Gemini Enterprise Agent Platform) are fine. The source Deloitte article is endnote 1.
- New sources get the next endnote number in order of first citation in the handbook; add them to both files. The deck's endnote slides (59–64) carry the same text and omit links by design.
- Endnote ranges: 1–100 are first cited in the main sections, 101–119 in the reference use cases. A new source in the main sections renumbers everything after it; keep the superscripts, Appendix A, Appendix B and the deck in step.
- The quantum briefing numbers its own endnotes (1–16) in order of first citation. When it cites a source that is also in the shared list, use the same wording.
- Use cases stay vendor-neutral except transactional systems of record (SAP S/4HANA, Workday, Snowflake, CRM). Their "realizing" sections cover MuleSoft Agent Fabric and Informatica only.
- Informatica is described as "Informatica from Salesforce" (Salesforce positions it as the trusted data foundation for AI agents).
- Business-case values and KPI baselines are illustrative; say so wherever they appear.
- Phased value (Section 8 and each use case): milestones at months 3, 8, 12 and 24; values are illustrative run rates derived from each use case's business case and KPI table, before platform, model and change costs; cumulative value counts each run rate from the milestone at which it was reached. The use cases come from different industries, so never add them up.

## Deck design system

- Plus Jakarta Sans; navy `0F172A` title and closing slides; light `F8FAFC` content slides; sky accents `0284C7` / `38BDF8`; 13.33 × 7.5 in (LAYOUT_WIDE).
- The deck embeds the original Plus Jakarta Sans subset (`build/fonts/*.fntdata`). Only characters listed in `build/allowed_chars.txt` render; `post_deck.py` reports anything else. Avoid →, ≥, ≈, ✓ and letters such as š in slide text (write "to", "or higher", "~", "Tomasev").
- Every slide carries speaker notes; slides that cite sources carry a "Sources: endnotes …" footer.

## Rebuilding (optional)

Requirements: Node 18+, Python 3 with Pillow, LibreOffice and poppler for previews. Install `build/render_fonts/*.ttf` first: they are the embedded subset with ligature substitution removed, so "fi" and "ffi" render correctly in previews.

```
cd build
npm install
npm run deck                     # out/JRF_The_AI_Control_Plane.pptx (embeds fonts, checks glyphs)
node build_uc_diagrams.js        # then: python3 render_figs.py diagrams  -> figs/uc*.png
python3 render_figs.py deckfigs out/JRF_The_AI_Control_Plane.pptx   # handbook Figures 1-7
npm run handbook                 # rebuilds the reference copy only (out/…); never copy it over the master
npm run assess                   # assessment toolkit: client deck, client report template, guide figures, guide, table check
```

Handbook Figures 1–7 are crops of deck slides 6, 10, 14, 21, 22, 23 and 26; Figures 8–22 are the `figs/uc*.png` diagrams. Word does not track pictures, so note any figure swap in a comment.

The toolkit's steps can also run one at a time: `npm run assess-deck`, `assess-client`, `assess-figs` (needs LibreOffice and poppler; renders `figs/assess_*.png` from the client deck and the template), `assess-guide` and `assess-check`. Build the deck and the template before the figures, and the figures before the guide. The guide's Figures 2–4 and 9–14 reuse `figs/fig4.png`, `fig5.png`, `fig7.png` and `uc1_*.png`. The builds write to `build/out/`; copy the results to `deliverables/` when they are final.

If packages cannot be installed, edit the Office files directly; the scripts are a convenience, not a requirement.
